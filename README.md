## Overview
**SPACER GOES LOFTING** is a spaceship design editor built for **SPACER GOES FISHING** *(currently a work in progress)*.

The tool is designed so that anyone can use it — keeping the workflow simple, intuitive, and self-explanatory. Its main goal is to speed up ship creation during active development while also making future modding easy for the community. Beyond that, it can also be used as a standalone design tool for other games or completely unrelated projects.

## Features
- **Procedural Hull Assembly:** Build ship hulls from basic geometric primitives (such as rectangles and simple shapes) with an intuitive workflow where newly placed sections snap together and merge seamlessly via automatic, procedural joints.
- **Functional Modules:** Outfit ships with a variety of specialized hardware — including multiple types of engines, antennas, sensors, turrets, batteries, and other subsystems.
- **Parametric Module Scaling:** Dynamically stretch and resize individual components directly on the hull. Physical scale directly governs capability — enlarging an engine proportionally increases its output, while scaling up a battery boosts its capacity.
- **Paint, Patterns & Markings:** Customize parts with custom colors and grid-aligned paint patterns, and apply manufacturer logos, corporate branding, or hull decals.
- **Geometry-Driven Physics & Stats:** Every design decision matters — a ship's physical properties and gameplay statistics are derived directly from its structural layout, mass, and installed components.

> *Note 1: **SPACER GOES LOFTING** is in early development; several of the features listed above are currently planned or work in progress.*

> *Note 2: The features above are described in the context of **SPACER GOES FISHING** — for other projects, the same geometry and metadata workflow can be adapted to completely different use cases.*

## Ship Data Format
**SPACER GOES LOFTING** uses a custom `.loft` file format — a structured, human-readable text format inspired by **JSON** and **SVG**.

Its main goal is to store **2D shape geometry** enriched with **depth data** and **custom metadata** in a single file:

- **2D Geometry:** Built by combining basic geometric primitives (boxes, simple polygons, modular parts) rather than drawing sleek, aerodynamic fighter hulls — reflecting a grounded space setting where aerodynamics don't matter and ships are utilitarian assemblies.
- **Height & Depth (3rd Dimension):** Non-visible Z-axis / elevation data that isn't rendered as a full 3D model (I mean, it can be if you really want it to), but provides spatial information for the lighting system — defining how light sources behave and how shadows are cast across the ship.
- **Metadata:** Structured key-value properties attached to the whole file or individual shapes, such as parameters, tags, or editor data (similar to JSON).
- **Human-Readable:** Plain-text structure that is easy to inspect, parse, and track in Git.

> *Note: The `.loft` specification is currently a work in progress and subject to change.*
